# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Docusaurus 3 site for ConCat (concat.app), an event/convention management product. It holds the marketing pages (home, pricing, policies), the end-user guides, and the public API reference. Docs are written in Markdown/MDX; there is no application code or test suite here.

## Commands

Use **npm** (`package-lock.json` is committed). Node `^26` is required.

- `npm install`: install dependencies
- `npm start`: dev server with live reload
- `npm run build`: production build into `build/`. Run this to validate changes: `onBrokenLinks: 'throw'` makes any broken internal link fail the build.
- `npm run serve`: serve the built `build/` directory
- `npm run typecheck`: `tsc` over `src/` and the root JS config files, with every strictness flag on (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, unused-code checks, ...). Docusaurus compiles via Babel, so this is the only type gate. Use `import type` for type-only imports.
- `npm run format` / `npm run format:check`: Prettier (`.prettierrc.json`: single quotes, width 120). `docs/` and all Markdown are excluded in `.prettierignore` because Prettier doesn't fully support MDX 3, so don't run Prettier on content files.
- `npm run clear`: clear the `.docusaurus` cache when the dev server behaves oddly

## Structure

- `docs/guides/`: user-facing guides, shown in `tutorialSidebar`
- `docs/api/`: API reference, shown in `apiSidebar`. Endpoints are split into `endpoints/v0/` (current) and `endpoints/legacy/`.
- Both sidebars are **autogenerated** from folder structure (`sidebars.js`). Ordering and labels come from `_category_.json` in each folder (`label`, `position`) and `sidebar_position` in page frontmatter. Adding a page means picking a `sidebar_position`; adding a folder means adding a `_category_.json`.
- `src/pages/`: standalone React pages (`index.tsx`, `pricing.tsx`, `policy/*`)
- `src/components/`: React components, each with a co-located `*.module.scss`. Global styles live in `src/css/custom.scss` and `_variables.scss` (SCSS via `docusaurus-plugin-sass`). Use the module system, not the APIs Dart Sass 3 removes: `@use '@site/src/css/variables' as *;` (not `@import`) and `color.adjust()` from `@use 'sass:color'` (not `darken`/`lighten`).
- `static/img/`: images, grouped by feature area (e.g. `img/cashier/`, `img/tutorial/`). Reference them as `/img/...`.

## MDX components

`src/theme/MDXComponents.tsx` swizzles the MDX mapper so these components are usable in any `.md`/`.mdx` file **without importing them**: `Highlight`, `Attribute`, `ParentAttribute`, `MaterialIcon`, `Link`, `RestElement`, `RestList`, `EndpointRequest`, `EndpointResponse`, `ExampleBox`, `SplitColumn`, `Card`, `BigButton`, `Admonition`. A new component meant for docs must be registered there.

`MaterialIcon` relies on the Material Symbols font loaded in `docusaurus.config.js` `stylesheets`.

## API reference page conventions

Follow the pattern in `docs/api/endpoints/v0/*.mdx` (e.g. `dealers.mdx`):

- Frontmatter: `displayed_sidebar: apiSidebar` and `hide_table_of_contents: true`.
- The page opens with a `<SplitColumn>`: a description on the left and a `<RestList>` of `<RestElement method path anchor>` on the right. Each `anchor` must match the slug of a `###` heading further down.
- Each endpoint is a `###` heading followed by a `<SplitColumn>`: the left side has Authentication (link to `/docs/api/gettingstarted/oauth` plus the required scope), then the Request and Response fields as `<Attribute>`/`<ParentAttribute>`; the right side has `<EndpointRequest>`/`<EndpointResponse>` JSON examples.
- `Attribute` `id`s must be unique within the page, so they use a short per-endpoint prefix (e.g. `su-`, `su-resp-`).
- Shared object models live in underscore-prefixed partials (`_registrationModel.mdx`, `_volunteerModel.mdx`). Docusaurus doesn't render these as pages; import them with `import X from './_xModel.mdx'`.

## CI & deployment

GitHub Actions (`.github/workflows/ci.yml`) runs `npm run format:check`, `npm run typecheck` and `npm run build` on pushes to `main` and on every PR, using the Node version from `package.json` `engines`.

The site is hosted on Cloudflare Pages. When `CF_PAGES_BRANCH` is set to anything other than `main`, `docusaurus.config.js` adds a red "preview version" announcement bar. `deploymentBranch` is `deployment` (used by `npm run deploy`). Commit messages follow Conventional Commits with a feature scope, e.g. `feat(products): ...`, `fix(api): ...`.
