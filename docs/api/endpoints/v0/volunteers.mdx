# Volunteers

## The volunteer object

- The application has no ID of its own in the response; use `user.id` to identify it.
- `user` is the applicant: `id`, `firstName`, `lastName`, `username`, `preferredName`, `email`, `phone` and `profilePictureURL`, plus `isStaff`. All but `id`, `profilePictureURL` and `isStaff` can be `null`.
- `contactMethods` lists how to reach the volunteer, each with a `name` and a `value`. The preferred one has `isPrimary: true`; on the others, `isPrimary` is left out rather than set to `false`.
- `departments` lists the departments the application mentions. Each has an `id`, a `name` and a list of `states`: `assignment`, `avoid`, `experience`, `interest` or `request`.
- `options` lists the volunteer's option answers. Each has an `id`, a `name`, a `type` (`address`, `currency`, `file`, `multi`, `number`, `phone`, `select` or `text`) and a `value`.
- `createdAt` and `updatedAt` are ISO 8601 timestamps. IDs are strings.

Hidden departments are included everywhere on this page.

## Paging

[Search volunteers](#search-volunteers) returns `{ "hasMore": …, "nextPage": …, "data": [ … ] }`. Leave `nextPage` out of the first request. While `hasMore` is `true`, send the `nextPage` value from the previous response to get the next page. On the last page, `nextPage` is left out of the response rather than set to `null`. An invalid `nextPage` returns logic error `112` (`BadPaginationToken`).

## Endpoints

### Search volunteers

Returns the current convention's volunteer applications, ordered by application. `limit` is 1 to 100, and defaults to 100. Scope: `volunteer:read`. [Full reference](/docs/api/endpoints/v0/reference/search-volunteers).

### Get a user volunteer application

Returns the user's volunteer application for the current convention, or a `404` resource error if they haven't applied. Scope: `volunteer:read`, or none when a user reads their own. [Full reference](/docs/api/endpoints/v0/reference/get-user-volunteer).

### List volunteer departments

Returns the current convention's departments, all at once rather than in pages. Each has an `id`, a `name`, the department's `email`, `publiclyVisible` (`false` for a hidden department), and its `leads` as user objects. Scope: `volunteer:read`. [Full reference](/docs/api/endpoints/v0/reference/list-volunteer-departments).
