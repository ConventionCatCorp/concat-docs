# Registration

## The registration object

- `uuid` identifies the registration, and `badgeId` is the number printed on the badge. `badgeName` can be an empty string.
- `status` is `paid` when the registration has been paid for, and `unpaid` otherwise.
- `productId`, `productName` and `productDisplayName` describe the paid-for product when `status` is `paid`, and the selected registration product otherwise. `productDisplayName` can be `null`.
- `order` is only present when the registration is paid. It holds the `orderId` and `orderItemId` that paid for it.
- `badgePrinted` is the ID of the user who printed the badge, or `null` if it hasn't been printed.
- `flags` lists the registration's flags, each with an `id` and a `shortName`.
- `options` lists the registration's option answers. Each has an `id`, a `name`, a `type` (`address`, `currency`, `file`, `multi`, `number`, `phone`, `select` or `text`) and a `value`.
- `user` is the registered user: `id`, `firstName`, `lastName`, `username`, `preferredName`, `email`, `phone` and `profilePictureURL`. All but `id` and `profilePictureURL` can be `null`.
- IDs are strings.

## Paging

[Search registrations](#search-registrations) returns `{ "hasMore": …, "nextPage": …, "data": [ … ] }`. Leave `nextPage` out of the first request. While `hasMore` is `true`, send the `nextPage` value from the previous response to get the next page. On the last page, `nextPage` is left out of the response rather than set to `null`. An invalid `nextPage` returns logic error `112` (`BadPaginationToken`).

## Endpoints

### Search registrations

Returns the current convention's registrations, ordered by user ID. `limit` is 1 to 100, and defaults to 100.

- `filter.userIds` is an array of up to 100 user IDs, as strings, to fetch the registrations of specific users.
- `filter.paidProductId` only includes registrations paid for with that product.

Scope: `registration:read`. [Full reference](/docs/api/endpoints/v0/reference/search-registrations).

### Get a user registration

Returns the user's registration for the current convention, or a `404` resource error if they haven't registered. Scope: `registration:read`, or none when a user reads their own. [Full reference](/docs/api/endpoints/v0/reference/get-user-registration).
