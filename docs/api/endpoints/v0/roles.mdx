# Roles

## The role object

- A role has an `id` (a string) and a `name`.
- In a user's list of roles, each role also has a `scope`: `convention` if it was granted for the current convention, or `global` if it was granted for the whole organization.

## Paging

Every list on this page uses the paging shape `{ "hasMore": …, "nextPage": …, "data": [ … ] }`, but only [List users with a role](#list-users-with-a-role) is actually paged. The other two return everything at once, with `hasMore` always `false` and no `nextPage`.

For [List users with a role](#list-users-with-a-role), leave `nextPage` out of the first request. While `hasMore` is `true`, send the `nextPage` value from the previous response to get the next page. On the last page, `nextPage` is left out of the response rather than set to `null`. An invalid `nextPage` returns logic error `112` (`BadPaginationToken`).

## Endpoints

### List roles

Returns every role defined in the organization. Scope: `user:read`. [Full reference](/docs/api/endpoints/v0/reference/list-roles).

### List users with a role

Returns the IDs of the users who hold the role, for the current convention or globally, ordered by user ID, as `{ "userId": "…" }` objects. `limit` is 1 to 1000, and defaults to 1000. Scope: `user:read`. [Full reference](/docs/api/endpoints/v0/reference/list-role-users).

### List the roles of a user

Returns the roles the user holds for the current convention, plus their global roles. Scope: `user:read`. [Full reference](/docs/api/endpoints/v0/reference/list-user-roles).

### Grant a role to a user

Grants the role to the user and returns an empty response. The request body is optional: set `scope` to `global` to grant the role for every convention in the organization; anything else grants it for the current convention only.

- If the user already has the role, for this convention or globally, you get logic error `10` (`UserAlreadyHasRole`).
- The roles that ConCat assigns itself (department lead, dealer assistant and role manager) can't be granted here. They return logic error `220`, `221` or `222`, telling you where in Housekeeping to assign the user instead.

Scope: `user:roles:update`. [Full reference](/docs/api/endpoints/v0/reference/grant-user-role).

### Remove a role from a user

Removes the role from the user and returns an empty response. Every grant of the role to the user in the organization is removed: the global grant, and the grants for each convention, not only the current one.

- If the user doesn't hold the role for the current convention or globally, you get a `404` resource error.
- The roles that ConCat assigns itself return logic error `220`, `221` or `222`, as for granting.

Scope: `user:roles:update`. [Full reference](/docs/api/endpoints/v0/reference/remove-user-role).
