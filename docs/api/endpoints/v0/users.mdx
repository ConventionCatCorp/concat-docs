# Users

<SplitColumn>
  <div>
    <p>
      A user is an account in the event organization: an attendee, a volunteer, a dealer, a staff member and so on. Users belong to the organization, not to one convention, so these endpoints return the same users on every convention's instance.

## The user object

- `id` is a string, like every ID in the v0 API.
- `firstName`, `lastName`, `username` and `email` are always present but can be `null`. `preferredName` and `phone` can also be `null`. A field that isn't set is returned as `null`, not as an empty string.
- `phone` is a string in international (E.164) format, for example `+15555555555`.
- `bornAt` is a date in `YYYY-MM-DD` format, or `null`.
- `address` is an object with `line1`, `line2`, `city`, `state`, `zipcode` and `country`, each of which can be `null`.
- `verified` is a boolean, and `profilePictureURL` is always a URL string.
- `ownerUserId` is the ID of the account that owns this one when the user is a sub-account, and `null` otherwise.

## Paging

[Search users](#search-users) returns `{ "hasMore": …, "nextPage": …, "data": [ … ] }`. Leave `nextPage` out of the first request. While `hasMore` is `true`, send the `nextPage` value from the previous response to get the next page. On the last page, `nextPage` is left out of the response rather than set to `null`. An invalid `nextPage` returns logic error `112` (`BadPaginationToken`).

## Endpoints

### Search users

Returns the organization's users, ordered by ID. `limit` is 1 to 1000, and defaults to 1000.

Narrow the results with one or more of these filters: `roleId`, `email`, or `ownerUserId` (to list a user's sub-accounts). Or use `search` for a free-text search; `search` can't be combined with the other filters, and doing so returns logic error `174` (`OnlySearchOrFilter`). With `search`, `nextPage` counts pages of search results instead of pointing at the last ID, but you use it the same way.

Scope: `user:read`. [Full reference](/docs/api/endpoints/v0/reference/search-users).

### Get a user

Returns a single user by ID. Scope: `user:read`. [Full reference](/docs/api/endpoints/v0/reference/get-user).

### Create a user

Creates a user account and returns `{ "id": "…" }`. Only `username` is required.

- If you leave out `password`, the account gets a random one. Set `sendEmail` to `true` to email the user a link to set their own; it's only sent when you also give an `email`.
- `reason`, at least 10 characters, is recorded in the audit log.
- `id` is only for organizations that reserve a range of user IDs, for example for administrators. It must be a number no higher than the last ID the organization has used; a higher one returns a validation error of type `number.max`.
- An email address or other unique value that is already in use returns a validation error of type `custom.unique`.

Scope: `user:create`. [Full reference](/docs/api/endpoints/v0/reference/create-user).
