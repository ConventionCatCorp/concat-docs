## The dealer object

- `id`, `name` and `email` are always set. The address fields, `addressLine1`, `addressLine2`, `addressCity`, `addressState`, `addressZipcode` and `addressCountry`, are always present but can be `null`.
- `user` is the user who owns the dealer profile: `id`, `firstName`, `lastName`, `username`, `preferredName`, `email`, `phone` and `profilePictureURL`. All but `id` and `profilePictureURL` can be `null`.
- `options` lists the dealer's option answers. Each has an `id`, a `name`, a `type` (`address`, `currency`, `file`, `multi`, `number`, `phone`, `select` or `text`) and a `value`.
- `applications` lists the dealer's applications. Each has:
  - `status`: `approved`, `pending`, `rejected` or `waitlisted`;
  - `dealerArea`, with an `id` and a `name`;
  - `tableType`, the table product applied for, where `paid` is `true` once the application has been paid for;
  - `dealerRequestTypes`, the extra products requested, each with its own `paid`;
  - `tableNumber` and `specialRequests`, which can be `null`;
  - `options`, the application's option answers.
- IDs are strings.

## Paging

[Search dealers](#search-dealers) returns `{ "hasMore": …, "nextPage": …, "data": [ … ] }`. Leave `nextPage` out of the first request. While `hasMore` is `true`, send the `nextPage` value from the previous response to get the next page. On the last page, `nextPage` is left out of the response rather than set to `null`. An invalid `nextPage` returns logic error `112` (`BadPaginationToken`).

## Endpoints

### Search dealers

Returns the current convention's dealers and their applications, ordered by user ID. `limit` is 1 to 1000, and defaults to 100.

The request accepts a `filter` object with a `userIds` array, but the results aren't filtered by it: every dealer is returned.

Scope: `vendor:read`. [Full reference](/docs/api/endpoints/v0/reference/search-dealers).
